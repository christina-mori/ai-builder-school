# AI Builder School

AI Builder School 的前端开发交接仓库，包含**学生端**与**教学运营中台**。当前实现用于确认界面和业务流程；后端伙伴可基于这份代码接入真实身份、数据库、文件存储与权限。

这是原生 HTML / CSS / JavaScript 项目，`dist/` 就是可编辑的前端源码和静态资源，不是需要重新构建的产物。无需安装依赖即可运行。

## 本地启动

需要 Python 3.9 或更新版本。在仓库根目录执行：

```sh
git clone https://github.com/christina-mori/ai-builder-school.git
cd ai-builder-school
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

| 入口 | 本地地址 |
|---|---|
| 学生端 · 暖色主题 | http://127.0.0.1:4173/ |
| 学生端 · 蓝色主题 | http://127.0.0.1:4173/bright/ |
| 教学运营中台 | http://127.0.0.1:4173/admin/ |

请通过 HTTP 打开，避免双击 HTML 造成存储或资源路径差异。更换浏览器、域名或端口会使用不同的本地数据；用 `4182` 等独立端口验证写入操作，可避免改动常用预览中的记录。

## 已实现的流程

| 学生端 | 教学运营中台 |
|---|---|
| 冒险大厅、八周旅程地图、独立任务页 | 教学概览、学员管理 |
| 锦囊分类筛选、查看与下载示例材料 | 锦囊、课件、附件管理 |
| 个人网站 / 个人知识库两项任务，草稿和版本记录 | 按周创建任务、关联材料、预览与模拟发布 |
| 广场、作者资料、点赞、好友申请演示 | 学员 CSV 导入预检与确认 |
| 资料编辑、头像上传裁剪、个人中心 | 作业反馈、状态与操作记录 |
| 手机导航、配色切换、首次使用指引 | 学员视角只读预览、桌面与窄屏布局 |

**两端尚未通过接口连通。** 中台的“发布”只改变当前浏览器的中台记录，不会更新学生端；中台的“学员视角预览”也不是实际学生端的数据源。

学生端使用 localStorage；中台使用 IndexedDB，包括本机附件 Blob。登录、验证码、好友、反馈和上传流程没有服务端身份或访问控制，不代表真实认证或跨用户协作。学生端 W1 有两项演示任务，后续周次尚未发布。仓库中仅含虚构示例数据，不包含本机浏览器存档。

## 后端伙伴从哪里开始

1. 阅读 [后端开发交接](docs/BACKEND-HANDOFF.md)：业务对象、建议接口、接入顺序与端到端验收。
2. 阅读 [前端结构与接入位置](docs/FRONTEND-ARCHITECTURE.md)：脚本加载顺序、存储入口和维护限制。
3. 阅读 [中台详细交接](ADMIN-HANDOFF.md)：现有表单、发布约束、附件和 CSV 规则。
4. 确认接口方案后，将学生端与中台的本地数据层逐步替换为同一套服务端 API。后端框架与数据库由接手伙伴决定，本仓库没有预设实现。

## 目录

```text
dist/
  index.html                # 暖色学生端
  app.js, learning.js       # 基础数据与旧页面 / 锦囊逻辑
  experience.js             # 当前学生端路由、任务、档案、社交演示
  resources.js              # 当前锦囊目录与查看 / 下载入口
  journey.js, realm.js      # 向导、旅程与全屏地图
  compare.js, onboarding.js # 配色 / 桌面紧凑导航、首次使用指引
  *.css                     # 基础样式与共享扩展
  bright/                   # 蓝色学生端入口与主题文件
  admin/                    # 独立中台入口、样式、业务与 IndexedDB
  resources/                # 六份可阅读 / 下载的示例 HTML
  assets/                   # 场景、导航图片、字体与许可证
scripts/                    # 项目检查及可选资源处理工具
docs/                       # 后端、前端结构、素材与交接验证说明
.github/pull_request_template.md # 后续协作的 PR 模板
  # 自动检查工作流模板另见 docs/ci/check.yml
```

目前页面通过普通 `<script>` 按顺序加载，多个扩展会重定义原有函数；不要随意改动脚本顺序。两套配色仍存在部分重复文件，修改公共行为时需核对两端。详细说明见架构文档。

## 检查与协作

运行检查需要 Node.js 22 和 Python 3.9+，不需要安装 npm 包：

```sh
python3 scripts/check-project.py
```

检查覆盖所有 JavaScript 语法、HTML / CSS 的本地静态引用和三个入口。它不能替代浏览器交互、权限或后端集成测试。手工检查清单和本次交接验证记录见 [验证说明](docs/VERIFICATION.md)。

后续从 `main` 创建功能分支，通过 Pull Request 合入；说明改动、影响页面与验证结果。视觉修改附桌面 / 手机截图。本地检查脚本已可用；自动检查工作流模板见 [docs/ci](docs/ci/README.md)。当前 OAuth 授权不能新增 Actions 工作流，因此本次没有安装远端 CI。模板只检查代码，不部署网站，也不更新 `gh-pages`。

临时截图、评审输出、本地托管配置、环境文件、日志和缓存由 `.gitignore` 排除。不要提交真实学员信息、浏览器存档、密钥或内部工作资料。

## 素材与辅助工具

字体及其上游许可证随仓库保留，场景和导航图片用于现有界面，详见 [素材与许可证说明](docs/ASSETS.md)。项目代码暂未指定额外的开源许可证，仓库公开不等于授予任意用途许可。

以下工具仅在修改对应内容时运行，启动网站无需运行：

- `node scripts/export-resources.cjs`：从现有锦囊定义导出示例 HTML。
- `python3 scripts/subset-ui-fonts.py`：重建界面字体子集；需要 `fonttools[woff]`。
- `node scripts/optimize-assets.cjs`：为脚本列出的 PNG 生成 WebP；需要 `sharp`。该脚本不处理所有新增素材，手工准备的无损地图与回退 PNG 需保留。
