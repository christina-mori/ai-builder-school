# 后端开发交接

交付日期：2026-10-29。范围：学生端两套配色、教学运营中台及静态资源。当前没有可调用的后端 API，下面的接口是接入建议，不是已实现或已锁定的契约。

## 优先跑通的业务闭环

课程负责人在中台创建任务、关联锦囊 / 课件并发布 → 同期学员在学生端看到任务和材料 → 学员保存草稿并提交作品 → 助教查看提交和留下反馈 → 学员看到反馈并提交修改版 → 两端能回看版本与操作记录。

这条流程完成前，不应把本地演示账户、模拟反馈或中台预览当作真实多用户系统。当前中台和学生端数据完全独立。

## 业务对象与关联

| 对象 | 建议关系与字段 | 现有前端位置 |
|---|---|---|
| 用户 / 期次成员 | 用户 ID、登录身份、期次 ID、角色、小组、助教 | 学生 `saved.profile`；中台 `students` |
| 周次 | 期次、周序号、标题、说明、发布状态 | `weeks`、中台任务 week |
| 任务 | 稳定 ID、期次、周次、说明、交付要求、截止、状态、版本 | `taskCatalog`；中台 `tasks` |
| 锦囊 / 课件 | 标题、介绍、领域、难度、维护人、状态、关联文件 | `resources`；中台 `resources` / `courseware` |
| 草稿 / 提交版本 | 用户 ID、任务 ID、作品名、链接、说明、问题、修改说明、版本号 | 学生 `draft` / `versions` |
| 反馈 | 提交版本 ID、助教 ID、正文、状态、创建时间 | 学生 feedback；中台 submissions.history |
| 文件 | 对象 key、文件名、MIME、大小、上传者、访问策略 | 中台 files 的本地 Blob |
| 社交关系 | 好友申请双方 ID、状态；作品点赞唯一关系 | `saved.social.requests` / `workLikes` |
| 审计 | 操作者、对象 ID、动作、前后状态、服务端时间 | 中台 logs 的本地演示 |

角色与可见范围需要在服务端按期次 / 小组明确：学员、助教、课程负责人 / 管理员。具体授权矩阵由后端与课程负责人确定。隐藏按钮、本地角色标签和前端筛选都不能作为授权依据。

## 建议接口分组

以下 `/api/v1` 路径用于沟通，可由接手伙伴调整。列表建议返回 `{items, nextCursor}`；错误建议返回 `{code, message, requestId, details?}`。日期存储用 UTC ISO，展示与截止时间输入统一 Asia/Shanghai。写入接口按需要加入幂等键与并发版本号。

| 分组 | 示例接口 | 要点 |
|---|---|---|
| 会话 | `GET /me`、登录 / 退出 | 选择正式认证方案；移除固定验证码，服务端验证会话 |
| 学员 | `GET/POST /cohorts/{id}/students`、`PATCH /students/{id}` | 搜索分页、成员范围与字段校验 |
| 导入 | `POST /cohorts/{id}/student-imports/preview`、`POST /student-imports/{id}/confirm` | 服务端再次校验编号、重复和权限，确认时事务写入 |
| 材料 | `/resources`、`/courseware` 的列表、详情、创建、编辑、发布 / 撤回 | 学员仅能读取有权访问的已发布版本 |
| 文件 | `POST /uploads`、上传完成确认、受控查看 / 下载 | 上传元数据和二进制分离，不把 Blob 塞进 JSON |
| 任务 | `/cohorts/{id}/weeks`、`/tasks` CRUD 与发布 / 撤回 | 发布时重验关联材料；修改保留版本与说明 |
| 草稿 | `GET/PUT /tasks/{id}/draft` | 按当前用户隔离，明确覆盖 / 并发策略 |
| 提交 | `POST /tasks/{id}/submissions`、查询本人 / 授权范围提交 | 版本只增不覆盖；校验 URL、说明与修改说明 |
| 反馈 | `POST /submissions/{id}/feedback`、查询历史 | 绑定具体版本、真实操作者；需修改必须填写建议 |
| 广场 / 社交 | 已授权作品列表、点赞、好友申请及处理 | 不伪造总数；只能由收件人同意、发件人撤回 |

这是建议，不要求首轮把社交功能与教学主流程同时上线。优先完成身份、材料发布、提交、反馈和版本闭环。

## 锦囊 DTO 映射

学生端目前使用以下字段；中台的 `url` 只是查看链接，不能直接当下载地址：

```json
{
  "id": "resource-id",
  "title": "材料标题",
  "desc": "用途说明",
  "type": "网页与应用",
  "level": "入门",
  "pixel": "book",
  "openUrl": "https://materials.example/lesson/",
  "downloadUrl": "https://files.example/download/lesson.zip",
  "fileName": "lesson.zip",
  "format": "ZIP 资料包",
  "publisher": "维护人",
  "sample": false
}
```

查看与下载应独立配置；没有原文件就返回无下载能力，不能把摘要另存为文件冒充原件。HTML 有相对素材时需要完整打包目录。下载响应应提供正确 MIME、原始文件名与 attachment；跨域 `download` 属性本身不能保证强制下载。登录页与上传的主动 HTML 内容需隔离来源。

## 发布与版本规则

- 材料、课件和任务分别有 draft / published / archived 状态。
- 发布任务时，重新确认其引用的材料已发布且有权关联。
- 修改已发布内容应产生版本或明确撤回后修改，不能静默改变学员已经领取的要求。
- 学员作品保留每次提交的说明与链接；外部网页可能变化，不等于内容快照。是否保存作品文件 / 快照需另行确定。
- 助教反馈必须能追溯对应提交版本，不能只覆盖一段“最新反馈”。

## 建议开发顺序

1. 确定部署、认证、用户 / 期次 / 小组与权限模型。
2. 学员管理与导入、文件存储、材料 CRUD 和发布。
3. 任务与关联材料，学生端读取同一份发布内容。
4. 草稿、正式提交、版本与助教反馈。
5. 服务端搜索分页、幂等与冲突处理、审计、备份 / 恢复和监控。
6. 根据实际需要接入社交、消息与通知；未接入部分保留明确的演示标识或隐藏入口。

## 接入验收

使用不同浏览器 / 登录账号测试，不能仅在一个浏览器中切换本地演示角色：

- 管理员创建并发布 W1 任务，学员账号可读，其他期次及未发布内容不可读。
- 学员上传 / 打开材料、提交网站或知识库成果；刷新和更换设备后仍可见。
- 助教只看到授权范围内的提交，反馈写入具体版本。
- 学员看到反馈并提交 v2，v1 和其反馈仍可回看。
- 请求失败不显示成功，不丢表单；重复点击不生成重复提交。
- CSV 导入错误不部分写入；同名不误合并；并发编辑有冲突提示。
- 文件下载实际落盘且名称 / 内容正确；未授权用户不能通过复制 URL 越权访问。
